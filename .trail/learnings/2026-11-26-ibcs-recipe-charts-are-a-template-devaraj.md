## Decided
- **Recipes are template plus bindings.** On 2026-11-26 the user asked for IBCS through public definitions only. A recipe (C01–C13) is written the way Fabric saves an added chart: the same template in both `chartType` selectors, plus pivot assignments in the template's buckets (axis, stack, AC/PY/PL/FC). Every chart names its template, including the plain column chart.
- **Charts keep the IBCS chart theme.** Later that day the user reported wrong colors on a built IBCS page (black bars, the Plan palette on a stack) and asked for the IBCS color codes from the IBCS site and the chart code. Every chart built from a recipe or a native template now saves one appearance setting:
  - IBCS as the chart's own theme;
  - a complete measure style for each bound role;
  - the variance colors.
- **IBCS is the default for template-only charts too.** The user chose this on 2026-11-26, because an IBCS chart that cannot meet a recipe's minimum bindings is built from `chartType` alone. `"theme": "plan"` opts a chart out. This changes existing template-only specs: a stack now shows greys in place of the Plan palette.
- **Color codes come from the chart's IBCS theme.** They were generated by running the product's own theme and measure-style code, not typed by hand. IBCS Standards 2.0 fix the notation (UN 3.2 scenarios, UN 4.1 variances, SI 2.2 no decorative colors) and say they do not prescribe exact codes.
- **Earlier choices stand.**
  - Set the Plan theme (`theme.type` 5) only on an explicit IBCS-theme request.
  - Show IBCS tables as a Matrix, with a message title and footnotes.
  - Skip the asterisk indicator. Charts from earlier builds with the generic `category` bucket are not repaired.

## Tried and ruled out
- **Reproducing the whole theme switch.** Picking a theme also changes about thirty settings outside the appearance: title mode, comparison notation, data labels, number scaling. Several are replaced whole on load, so a partial copy would break them.
- **Theme name without measure styles.** When the Plan theme is also IBCS and the sheet has not been themed yet, the chart merges the Plan theme and leaves the bound roles without colors.
- **A custom Plan theme carrying the codes.** The public plan-properties schema allows only the theme type, and custom themes live in user preferences.
- **Per-chart AI schema slice.** The page loader never reads it back, and it needs the Plan AI assistant switch, which is off by default.
- **Flagging authored charts as new.** Nothing clears the flag, so the full theme would re-apply on every load and wipe user edits.

## Watch out
- **Why bars were black.** A chart saved without measure styles gets empty style entries when the Plan theme is merged on load, and a bar without a fill color renders black. This was traced in product code and matches the screenshot. It was not reproduced in a running chart. Plain column charts and charts built with `"theme": "plan"` are still exposed.
- **Partial chart state.** A saved appearance is deep-merged over the chart's defaults, so a partial one is safe. KPI controls, comparison mapping, chart mode and ranking are replaced shallowly: write those complete or not at all.
- **A chart starts on the Customize theme**, which takes its colors from the Plan theme. It is not IBCS.
- **Difference from the standard.** The theme's neutral variance is light grey where the standard says blue.
- **Not verified in Fabric.** The live export needed a fresh sign-in. Still unconfirmed from an export: the stack field's filter card, PL/FC filter cards under bucket AC, Matrix slicer scope.
- **Fixture upkeep.** Regenerate the fixture when the product's IBCS theme changes. The generator is in the local findings folder.
